# Contributing to Windgram

Windgram combines a Python publication pipeline, versioned static documents,
the `windgram` TypeScript package, and a documentation and research site. A
change is complete when the implementation, contract, tests, and any prose it
makes stale land together.

Before starting, read [`AGENTS.md`](AGENTS.md). Its authority rules, provider
verification requirements, and research/reference boundaries apply to every
contribution.

## Set up and run the full check

The repository requires Python 3.12 or later, `uv`, and the pnpm version pinned
in the root [`package.json`](package.json). From the repository root:

```sh
corepack enable
pnpm install --frozen-lockfile
uv sync --project pipeline

uv run --project pipeline windgram scenarios check
uv run --project pipeline pytest pipeline/tests
pnpm --dir toolkit test
pnpm --dir toolkit typecheck
pnpm --dir scripts figures:check
pnpm --dir site check
pnpm --dir site build
```

The scenario check is read-only. If it reports drift, edit a recipe, baseline,
or generator, then [regenerate the scenario](#add-or-change-a-synthetic-scenario).
Do not patch the reported output. The figures check regenerates the committed
doc figures under `assets/` from the built package and fails on drift;
after an intentional renderer or composition change, run `pnpm --dir scripts figures` and
commit the regenerated assets.

## Know which file is authoritative

| Concern | Authoritative input | Generated or derived output |
| --- | --- | --- |
| Profile and catalogue contract | `toolkit/src/contract/index.ts` | `toolkit/schema/*.schema.json` |
| Site catalogue | `sites.json` — identity and build selection only (slug, name, coordinates, timezone) | Site blocks embedded in manifests and profiles; the catalogue itself published verbatim to the dataset root |
| Site ground truth | The catalogued coordinates, measured by `windgram terrain` from open elevation and land-cover data | `site-context.json` (the launch elevation pick, terrain analysis, land cover), committed and published beside the catalogue |
| Model catalogue | `models.json`, checked against builder behaviour and verified provider reference | Model manifests and profiles under `<model>/` in the published dataset |
| Pipeline derivations | `pipeline/src/windgram/` | `derived.*` values in profile documents |
| Package derivations and renderer | `toolkit/src/` | `toolkit/dist/`, golden SVG fixtures |
| Teaching scenarios | `scenarios/scenario.schema.json`, `scenarios/definitions/*.json`, source baselines, and `pipeline/src/windgram/scenarios.py` | `scenarios/generated/*.profile.json` and `scenarios/index.json` |
| Committed doc figures | `scripts/generate-doc-figures.mjs` with committed scenario profiles | `assets/*.svg` and `site/public/social-card.png` |
| Research article | `site/src/content/research/*.mdx` | Route, archive entry, and navigation generated by the content collection |

`runs.json`, model manifests, current profiles, and history archives are
publisher output served from <https://data.meteo.azohra.com>, not repository
content. Do not hand-edit or commit them. The same applies to `site/dist/`,
`toolkit/dist/`, the scenario registry, generated scenario
profiles, and the committed doc figures under `assets/`. Lockfiles are machine-maintained through `uv` or the workspace-pinned
pnpm, not edited as prose.

The current version axes and their compatibility rules are documented in
[Data and package versioning](https://windgram.azohra.com/docs/data/versioning/).
They move independently.

## Choose the contribution path

### Add or correct a site

1. Edit the versioned envelope in [`sites.json`](sites.json). The slug is the
   stable identity; the entry carries identity and build selection only —
   slug, name, coordinates in decimal degrees, and the IANA timezone. There
   is no elevation field: humans author WHERE, the pipeline measures WHAT,
   and the loader rejects a typed-in `elevationM` with directions.
2. Regenerate the measured ground truth and commit it with the catalogue:

   ```sh
   uv sync --project pipeline --extra terrain
   uv run --project pipeline windgram terrain
   ```

   This rewrites [`site-context.json`](site-context.json) — the site's launch
   elevation pick (LidarBC 1 m ground returns → MRDEM-30 → GLO-30 as a loud
   last resort), terrain analysis, and land cover — and prints a one-line
   summary per site. Read the summaries and any `WARN` lines before
   committing: a large pick-versus-terrain gap usually means the coordinates
   are wrong.
3. Add or update coverage in [`pipeline/tests/test_sites.py`](pipeline/tests/test_sites.py).
4. Run `uv run --project pipeline pytest pipeline/tests/test_sites.py`, then the full Python suite. Every
   builder reads the same catalogue, so a catalogue change is not isolated to
   one model.

Do not add a current profile or manifest by hand. A successful builder publishes
the site only for models whose domains cover its coordinates.

### Add or change a forecast model

Provider facts must be verified against the live feed before code is written.
Record paths, fields, levels, sentinels, packing, cadence, semantics, and limits
with a dated `[verified YYYY-MM-DD]` entry in
[`site/src/content/docs/docs/reference/forecast-model-feeds.mdx`](site/src/content/docs/docs/reference/forecast-model-feeds.mdx).

Then:

1. add or update the declaration in [`models.json`](models.json);
2. implement builder behaviour under `pipeline/src/windgram/builders/` without filling
   an absent capability with a synthetic zero or inferred value;
3. add focused fixture-based tests in `pipeline/tests/builders/test_<model>.py` (or the
   shared builder test where that is the existing home);
4. assert that catalogue capabilities and transport semantics match the
   builder; and
5. update the scheduled publisher only when the model is ready to publish.

Run the focused builder tests and `uv run --project pipeline pytest pipeline/tests`. If a contract shape changes,
also run the [contract and package checks](#change-the-published-contract-or-npm-package). Tests must not need a live provider;
verification establishes facts, while committed fixtures make the suite
repeatable.

### Add or change a synthetic scenario

Follow the [scenario authoring guide](https://windgram.azohra.com/docs/contribute/scenario-authoring/).
Edit a definition or source baseline, keep its identity synthetic,
and regenerate the repository outputs:

```sh
uv run --project pipeline windgram scenarios generate
uv run --project pipeline windgram scenarios check
uv run --project pipeline pytest pipeline/tests/test_scenarios.py pipeline/tests/test_scenario_ensembles.py
```

Commit the definition, any intentional baseline or generator change, the
generated profile or profiles, and `scenarios/index.json` together. A new
lesson needs machine-checkable assertions. Never author `derived.*` in a
definition or baseline; the production derivation is its one home. The
launch a scenario teaches against lives in the definition's `launch` block
and is published in the index entry — never in a baseline or a generated
document, which are launch-agnostic like production profiles.

### Add or change a figure

Follow the [visual authoring guide](https://windgram.azohra.com/docs/contribute/visual-authoring/).
Reusable figure structure belongs in `site/src/components/figure/`; a
figure composition lives with its consumer — `site/src/components/docs/`
for portal pages, `research/` for research articles, `about/` and `home/`
for those pages. Place a figure explicitly in the MDX source that
discusses it.

Scenario-driven figures resolve committed teaching data through the site's
scenario library and make no request for current forecast data. Run:

```sh
pnpm --dir toolkit test
pnpm --dir site check
pnpm --dir site build
```

Review the static pre-hydration result, keyboard and touch controls,
reduced-motion state, mobile layout, units, caption, and textual equivalent.

### Add or change a research article

`site/src/content/research/` is the canonical research ledger. Add an MDX file
with the complete validated frontmatter (`title`, `summary`, `section`, `kind`,
`published`, `updated`, `status`, `order`, `scenarios`, and `thumbnail` — the
thumbnail enum lives in `site/src/content.config.ts`). The content
collection creates the route, the navigation, and the published
[research archive](https://windgram.azohra.com/research/); do not add a
hard-coded article registry.

A research entry is a dated account of substantive work, not a roadmap,
session log, or place to duplicate living provider facts. Provider inventory
stays in the portal's reference pages; working notes stay uncommitted in
`notes/`. Propose a substantive rewrite of another author's prose before
landing it.

Run `pnpm --dir site check` and `pnpm --dir site build`. These validate
frontmatter, imports, and generated routes; confirm that the built article's
internal links resolve as part of review.

### Change the published contract or npm package

The zod contract and TypeScript types in
`toolkit/src/contract/index.ts` are the source. Keep JSDoc and the
matching `.describe()` text equivalent so TypeScript and non-JavaScript
consumers receive the same semantics. Regenerate JSON Schema artifacts after
an intentional contract edit:

```sh
pnpm --dir toolkit schemas
pnpm --dir toolkit test
pnpm --dir toolkit typecheck
```

The contract test deep-compares the emitted schemas with the committed files.
Do not edit `toolkit/schema/*.schema.json` directly. Update the npm
version only for a deliberate package release, and do not change the Python or
dataset version merely to make the numbers match.

## Forecasts, scenarios, and attribution

Published forecast artifacts in the dataset identify a real provider, model,
run, and site. Teaching scenarios use fixed synthetic identity and time. They
may be calibrated offline from real output, but public figures remain synthetic
and must not present calibration timestamps as conditions, hindcasts, or
expectations at a launch.

When real provider material informs a baseline, record it in a sibling
provenance record; the required fields are listed in
[`scenarios/README.md`](scenarios/README.md#baselines-and-attribution), next
to the baselines they describe. ECCC-derived material retains the ECCC end-use licence attribution;
NOAA material should credit NOAA and the named product even where the source is
public domain. Cite scientific methods and borrowed conventions adjacent to
the claim they support.

Code is distributed under the repository's [MIT licence](LICENSE). Cite a
released repository state using [`CITATION.cff`](CITATION.cff); a citation does
not replace provider attribution for data-derived material.

## Golden SVG policy

Golden files under `toolkit/test/golden/` protect the reference
renderer and selected scenario output. A mismatch is a review request, not an
instruction to accept new pixels. The review-then-update sequence is
maintained in
[Tests by change](https://windgram.azohra.com/docs/contribute/tests/#golden-svg-changes-require-review).

## Pull-request checklist

- The diff edits authoritative inputs and regenerates outputs with their owner
  command.
- Tests cover the changed behaviour and the focused and full relevant suites
  pass.
- Published prose, reference facts, examples, and changelog entries remain
  true.
- Optional or unavailable provider data remains absent rather than zero-filled.
- Scenario definitions use non-production model and site slugs.
- Provider and method attribution is adjacent and complete.
- No current forecast fetch or operational result browser is introduced into
  the project website.
